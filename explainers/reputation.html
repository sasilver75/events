Spontaneous Events · v0

Reputation, in two inputs.

Did you show up? Did anyone name a real concern? That's it. Everything else (👍s, soft 👎s, ratings) is captured for bundled feedback to the user but doesn't move the score.

# Final score, 0–100 score = clamp(round(behavioral * flag_factor), 0, 100) # Behavioral — Bayesian Bernoulli, severity-weighted, time-decayed posterior_α = 4.0 + Σ (e.success_weight * decay(e.age_days)) posterior_β = 1.0 + Σ (e.failure_weight * decay(e.age_days)) behavioral = (posterior_α / (posterior_α + posterior_β)) * 100 # Flag factor — multiplicative penalty, decayed counts weighted_flags = Σ decay(flag.age_days) flag_factor = max(0.4, 1 - 0.12 * weighted_flags) # Decay — exponential, 2-year half-life decay(age_days) = 0.5 ** (age_days / 730)

Variables in the formula

score
Final reputation, integer 0–100. What gets stored on the user row and shown in the UI.
behavioral
The "did they show up reliably?" component. Float 0–100, derived from a Bayesian Bernoulli over a user's event outcomes (Shows, Ghosts, Flakes), severity-weighted and time-decayed.
flag_factor
The "did anyone name a real concern?" multiplier. Float in [0.4, 1.0]. Multiplies behavioral down — never up.
posterior_α
Bayesian "successes" count: the prior (4.0) plus all decay-weighted event successes a user has accrued.
posterior_β
Bayesian "failures" count: the prior (1.0) plus all decay-weighted event failures. The prior makes new users start at ~80, drifting toward their true rate as evidence accrues.
e
A single past event the user Committed to. Iterated over to build the posterior.
e.success_weight
How much this event contributes to "successes" — depends on outcome (see Event outcomes below).
e.failure_weight
How much this event contributes to "failures" — same source. Severity is encoded here (Ghost weighs 3× a Flake's 1.5×).
e.age_days
How long ago the event happened. Feeds decay().
weighted_flags
Sum of all flags this user has received, each multiplied by its own decay factor. Old flags weigh less.
flag.age_days
How long ago a given flag was received.
decay(age_days)
Exponential time-decay function with a 2-year half-life. 0.5 ** (age_days / 730) — at 0d = 1.0, at 730d = 0.5, at 1460d = 0.25.

Event outcomes

Every event a user Committed to ends in exactly one of these outcomes. Show vs Ghost is determined by objective signals only — check-in tap or passive location confirmation. No peer attestation enters the presence decision (per ADR 0009).

Show
Presence confirmed by either a check-in tap (geofence-gated, ~50m of the pin) or passive location confirmation (any GPS sample within ~150m of the pin during the event window — requires "Always Allow" location permission).
Ghost
No Withdraw, no check-in, no passive location confirmation. The strongest behavioral negative.
Flake
The user Withdrew, but inside the "late" window (post-Tip on β-Events; <2hr from Live on either shape). Costly-but-honest.
Early Withdraw
The user Withdrew outside the late window. Clean — does not count against the score at all.
Flag
A 👎 with at least one "hard reason" selected (e.g., "concerning behavior," "would not attend with again"). Orthogonal to Show/Ghost — flags never determine presence; they only drive flag_factor. Invalidated if location data demonstrably places the flagged user elsewhere during the event window.

Why Bayesian smoothing?

The cold-start problem

The naive formula is score = shows / total_events × 100. Simple, but broken at low data. A new user with 1 event who Ghosts is at 0/1 = 0% — indistinguishable from a chronic ghoster with 100 events and 100 ghosts. That's wrong: we have 1 data point, not 100. We don't know anything about them yet.

The prior as "phantom events"

Bayesian Bernoulli baked a starting belief into the math, expressed as imaginary events every user starts with:

α=4, β=1 means "before we've seen anything from this user, we believe they behave like someone who has Shown up 4 times and failed 1 time." That puts them at ~80% expected reliability — the "New" baseline.

Each real event nudges that belief toward the user's true rate. The math (Beta-Bernoulli posterior mean):

posterior_mean = (α_prior + successes) / (α_prior + successes + β_prior + failures)

Why "severity-weighted"?

Pure Bernoulli treats all failures equally — a Ghost would weigh the same as a Flake. We don't want that; a Ghost is structurally worse. So each outcome contributes a weighted amount to α (successes) and β (failures), with severity encoded directly in those weight values. It's no longer strictly Bernoulli (it's a generalization), but the posterior-mean intuition still holds: more weight in either column shifts the score correspondingly.

OutcomeAdds to α (success)Adds to β (failure)
Show1.00.0
Flake0.01.5
Ghost0.03.0
Early Withdraw0.00.0

A Ghost contributes 3× a Flake's failure weight. Early Withdraw is invisible to the score.

Walk-through

Plugging the severity weights from above into the posterior formula. α = prior 4 + Σ success_weights · β = prior 1 + Σ failure_weights · score = α / (α + β) × 100.

ScenarioαβScore
Brand-new user, no events4180
1 Ghost (failure weight 3.0)41 + 3 = 450
1 Ghost, then 5 Shows (success weight 1.0 each)4 + 5 = 9469
1 Ghost, then 20 Shows4 + 20 = 24486
50 Ghosts, no Shows (50 × 3.0 = 150 to β)41 + 150 = 1513

Two things to notice: (1) one bad event doesn't tank a new user — the prior buffers them. (2) With enough real events, the prior becomes irrelevant — reality dominates.

Two payoffs

  • Cold-start sanity. New users don't get punished for tiny sample sizes; ratings move smoothly from "what we'd assume of anyone" toward "what their record shows."
  • Confidence baked into the math. With more events, the prior fades and individual events have less swing. A reliable user with 50 Shows isn't tanked by one bad night.

Flag factor

Multiplicative penalty

Flags scale your score down — they don't just chip away at it. Floor at 0.4 bounds the worst case (e.g., coordinated harassment).

flag_factor as flag count grows

Decay — 2-year half-life

A flag (or behavioral event) from 1 year ago counts at ~71%; from 2 years at 50%; from 4 years at 25%. No hard cutoff. Old behavior fades; very old behavior is nearly gone but never truly zero.

weight = 0.5 ^ (age_days / 730)

Personas

What does not enter the score

  • 👍 thumbs-up — captured. Shown to the user in their bundled feedback ("3 people gave you 👍 from your last events"). Doesn't move the score.
  • 👎 with "I just didn't like them" — captured. Shown to the user as soft signal. Doesn't move the score.
  • 1–5 numeric ratings — not in v0. The ternary 👍/👎/skip pattern replaces them.

Score = trustworthiness, not popularity. Whether you charmed everyone is orthogonal. Did you show up? Did anyone name a real concern?
